# Python 面试题 300 问 300 答

## 一、语法基础

1. 问：Python 是编译型还是解释型语言？  
   答：通常认为是解释型语言，但源码会先编译成字节码，再由解释器执行。

2. 问：Python 的主要特点是什么？  
   答：语法简洁、标准库丰富、跨平台、开发效率高，适合脚本、后端、数据和 AI。

3. 问：`=` 和 `==` 的区别是什么？  
   答：`=` 是赋值，`==` 是值比较。

4. 问：`is` 和 `==` 的区别是什么？  
   答：`==` 比较值是否相等，`is` 比较是否为同一对象。

5. 问：Python 中哪些值会被判定为假？  
   答：`None`、`False`、`0`、`0.0`、空字符串、空列表、空元组、空字典、空集合等。

6. 问：列表和元组的区别是什么？  
   答：列表可变，元组不可变；列表适合频繁修改，元组适合只读数据。

7. 问：集合的特点是什么？  
   答：元素无序、唯一，适合去重和成员测试。

8. 问：字典的底层特征是什么？  
   答：基于哈希表实现，平均时间复杂度下查找、插入、删除都较快。

9. 问：什么是可变对象？  
   答：对象内容可以原地修改，如 `list`、`dict`、`set`。

10. 问：什么是不可变对象？  
    答：对象创建后内容不能修改，如 `int`、`str`、`tuple`。

11. 问：字符串为什么不可变？  
    答：不可变可以提升安全性、可哈希性和内部优化能力。

12. 问：`len()` 的作用是什么？  
    答：返回容器中元素个数。

13. 问：切片语法 `a[start:end:step]` 表示什么？  
    答：从 `start` 到 `end` 左闭右开，按 `step` 步长取值。

14. 问：负索引有什么用？  
    答：可以从尾部访问元素，如 `a[-1]` 表示最后一个元素。

15. 问：`range(5)` 会生成什么？  
    答：生成 0 到 4 的整数序列对象。

16. 问：`pass` 的作用是什么？  
    答：占位，不执行任何操作。

17. 问：`break` 和 `continue` 的区别是什么？  
    答：`break` 结束循环，`continue` 跳过本轮进入下一轮。

18. 问：`for` 和 `while` 的适用场景有何不同？  
    答：`for` 适合遍历，`while` 适合条件驱动循环。

19. 问：`enumerate()` 有什么用？  
    答：遍历时同时获取索引和值。

20. 问：`zip()` 有什么用？  
    答：把多个可迭代对象按位置打包。

21. 问：什么是解包？  
    答：把序列中的多个值一次性赋给多个变量。

22. 问：星号解包 `*rest` 的作用是什么？  
    答：接收剩余多个元素。

23. 问：`in` 操作符做什么？  
    答：判断成员是否存在。

24. 问：`del` 的作用是什么？  
    答：删除变量引用或容器中的元素。

25. 问：Python 中注释怎么写？  
    答：单行用 `#`，文档字符串常用三引号。

26. 问：什么是文档字符串？  
    答：写在模块、类、函数开头的字符串，用于说明用途。

27. 问：`type()` 的作用是什么？  
    答：查看对象类型，或动态创建类。

28. 问：`id()` 返回什么？  
    答：返回对象标识，通常可理解为对象在当前运行时的唯一身份。

29. 问：`sorted()` 和 `list.sort()` 区别是什么？  
    答：`sorted()` 返回新列表，`list.sort()` 原地排序。

30. 问：`reversed()` 返回什么？  
    答：返回一个反向迭代器。

31. 问：列表推导式的优点是什么？  
    答：写法简洁，通常比手写循环更清晰。

32. 问：字典推导式的格式是什么？  
    答：`{k: v for ...}`。

33. 问：集合推导式的格式是什么？  
    答：`{x for ...}`。

34. 问：生成器表达式和列表推导式的主要区别是什么？  
    答：生成器惰性计算，更省内存。

35. 问：Python 中如何交换两个变量？  
    答：`a, b = b, a`。

36. 问：`None` 表示什么？  
    答：表示空值或无返回结果。

37. 问：函数没有显式 `return` 会返回什么？  
    答：返回 `None`。

38. 问：`input()` 返回的类型是什么？  
    答：总是字符串。

39. 问：`print()` 默认结尾是什么？  
    答：默认结尾是换行符 `\n`。

40. 问：`sep` 参数有什么用？  
    答：控制 `print()` 多个参数之间的分隔符。

## 二、函数

41. 问：函数定义关键字是什么？  
    答：`def`。

42. 问：位置参数是什么？  
    答：按参数位置传值的参数。

43. 问：关键字参数是什么？  
    答：通过参数名传值的参数。

44. 问：默认参数有什么注意点？  
    答：默认值在函数定义时求值，可变对象做默认值容易出问题。

45. 问：为什么不建议用空列表作为默认参数？  
    答：会在多次调用间共享同一个对象。

46. 问：可变默认参数的常见写法是什么？  
    答：默认设为 `None`，函数内再初始化。

47. 问：`*args` 的作用是什么？  
    答：接收额外的位置参数。

48. 问：`**kwargs` 的作用是什么？  
    答：接收额外的关键字参数。

49. 问：仅位置参数怎么定义？  
    答：在参数列表中使用 `/`。

50. 问：仅关键字参数怎么定义？  
    答：在参数列表中 `*` 后面的参数就是仅关键字参数。

51. 问：什么是高阶函数？  
    答：接受函数作为参数或返回函数的函数。

52. 问：闭包是什么？  
    答：内部函数引用了外部函数作用域变量，并在外部函数结束后仍可使用。

53. 问：`nonlocal` 的作用是什么？  
    答：在闭包中修改外层局部变量。

54. 问：`global` 的作用是什么？  
    答：在函数内部声明并修改全局变量。

55. 问：匿名函数怎么写？  
    答：使用 `lambda`。

56. 问：`lambda` 有什么限制？  
    答：只能写单个表达式，不能写多条语句。

57. 问：递归是什么？  
    答：函数直接或间接调用自身。

58. 问：递归的风险是什么？  
    答：可能栈溢出，性能也可能较差。

59. 问：`map()` 的作用是什么？  
    答：把函数应用到可迭代对象的每个元素上。

60. 问：`filter()` 的作用是什么？  
    答：过滤满足条件的元素。

61. 问：`reduce()` 做什么？  
    答：把序列聚合成一个结果，位于 `functools` 中。

62. 问：装饰器本质是什么？  
    答：接收函数并返回新函数的语法糖。

63. 问：装饰器常见用途有哪些？  
    答：日志、权限校验、缓存、计时、重试。

64. 问：为什么装饰器里常用 `functools.wraps`？  
    答：保留原函数的名字和文档等元信息。

65. 问：函数是一等公民是什么意思？  
    答：函数可以赋值、传参、返回、存入容器。

66. 问：`yield` 的作用是什么？  
    答：把函数变成生成器函数，按需产出数据。

67. 问：生成器函数和普通函数返回值有何不同？  
    答：生成器函数返回生成器对象，不会立即执行完。

68. 问：`yield from` 的作用是什么？  
    答：把子生成器的值直接委托给外层生成器。

69. 问：如何查看函数参数签名？  
    答：可用 `inspect.signature()`。

70. 问：为什么函数要尽量短小？  
    答：更容易测试、复用、维护和定位问题。

## 三、数据结构与算法常识

71. 问：列表按索引访问的复杂度通常是多少？  
    答：通常是 O(1)。

72. 问：列表头部插入元素的复杂度通常是多少？  
    答：通常是 O(n)。

73. 问：字典查找的平均复杂度是多少？  
    答：平均 O(1)。

74. 问：集合查重为什么快？  
    答：因为底层基于哈希表。

75. 问：什么时候适合用 `deque`？  
    答：需要频繁从两端插入或弹出时。

76. 问：`heapq` 适合什么场景？  
    答：优先队列、TopK、最小堆。

77. 问：`bisect` 适合什么场景？  
    答：在有序序列中做二分查找和插入。

78. 问：什么是哈希冲突？  
    答：不同键计算出相同哈希槽位。

79. 问：为什么字典键通常要求可哈希？  
    答：因为要参与哈希计算并保持稳定。

80. 问：元组为什么常能作为字典键？  
    答：如果其元素都可哈希，元组本身就可哈希。

81. 问：列表为什么不能作为字典键？  
    答：列表可变，不可哈希。

82. 问：排序稳定性是什么意思？  
    答：相等元素排序后相对次序不变。

83. 问：Python 默认排序算法是什么？  
    答：Timsort。

84. 问：Timsort 的特点是什么？  
    答：稳定，且对部分有序数据表现好。

85. 问：如何按对象某个字段排序？  
    答：使用 `key` 参数。

86. 问：`key=lambda x: x[1]` 表示什么？  
    答：按每个元素的第二项排序。

87. 问：去重后还要保持顺序，常见做法是什么？  
    答：遍历加集合判重，或借助字典保序特性。

88. 问：TopK 问题常见方案有哪些？  
    答：排序、最小堆、快速选择。

89. 问：为什么说算法选择比语法更重要？  
    答：算法决定复杂度上限，直接影响性能。

90. 问：医疗问答项目里实体词典匹配更适合哪类数据结构？  
    答：Trie 或 Aho-Corasick 自动机，适合多模式串匹配。

## 四、面向对象

91. 问：类和对象的区别是什么？  
    答：类是模板，对象是实例。

92. 问：`__init__` 的作用是什么？  
    答：初始化实例属性。

93. 问：`self` 表示什么？  
    答：当前实例对象本身。

94. 问：实例属性和类属性有什么区别？  
    答：实例属性属于对象，类属性属于类并可被实例共享访问。

95. 问：`@classmethod` 的第一个参数通常是什么？  
    答：`cls`。

96. 问：`@staticmethod` 有什么特点？  
    答：不依赖实例和类状态，只是逻辑上归属类。

97. 问：继承有什么作用？  
    答：复用代码并表达 is-a 关系。

98. 问：多态是什么意思？  
    答：同一接口在不同对象上表现不同实现。

99. 问：方法重写是什么？  
    答：子类重新实现父类已有方法。

100. 问：`super()` 的作用是什么？  
     答：调用父类方法，支持多继承场景下的 MRO。

101. 问：MRO 是什么？  
     答：方法解析顺序，决定多继承中属性和方法的查找路径。

102. 问：鸭子类型是什么意思？  
     答：关注对象是否支持所需行为，而不是是否继承某个类。

103. 问：Python 更偏向哪种类型系统风格？  
     答：动态类型和鸭子类型。

104. 问：封装在 Python 中如何体现？  
     答：通过接口约定、命名习惯和属性控制来体现。

105. 问：单下划线前缀通常表示什么？  
     答：约定为内部使用。

106. 问：双下划线前缀会发生什么？  
     答：触发名称改写，降低子类误覆盖风险。

107. 问：`property` 有什么用？  
     答：把方法伪装成属性访问。

108. 问：为什么要用 `property`？  
     答：可以在不改外部调用方式的前提下加入校验逻辑。

109. 问：数据类 `dataclass` 的优势是什么？  
     答：自动生成 `__init__`、`__repr__`、比较方法等，减少样板代码。

110. 问：什么时候适合用 `dataclass`？  
     答：主要承载数据、逻辑较少的对象。

111. 问：抽象基类的作用是什么？  
     答：定义统一接口约束。

112. 问：`__str__` 和 `__repr__` 区别是什么？  
     答：`__str__` 面向用户，`__repr__` 面向开发调试。

113. 问：`__len__` 有什么作用？  
     答：让对象支持 `len()`。

114. 问：`__iter__` 有什么作用？  
     答：让对象可迭代。

115. 问：`__call__` 有什么作用？  
     答：让实例像函数一样被调用。

116. 问：组合和继承怎么选？  
     答：优先组合，只有确实是稳定的 is-a 关系时再用继承。

117. 问：为什么过深继承层级不推荐？  
     答：理解和维护成本高，耦合强。

118. 问：Python 中接口通常如何体现？  
     答：靠协议、抽象类或类型提示约束。

119. 问：对象拷贝分几种？  
     答：浅拷贝和深拷贝。

120. 问：浅拷贝和深拷贝的区别是什么？  
     答：浅拷贝只复制外层，深拷贝递归复制内部对象。

## 五、异常处理

121. 问：为什么要用异常机制？  
     答：把正常流程和错误处理分开，提高可读性和健壮性。

122. 问：`try/except` 的作用是什么？  
     答：捕获并处理运行时异常。

123. 问：`else` 在异常处理中何时执行？  
     答：只有 `try` 块没有异常时执行。

124. 问：`finally` 在异常处理中何时执行？  
     答：无论是否异常通常都会执行。

125. 问：为什么不建议裸写 `except:`？  
     答：会吞掉所有异常，难以定位问题。

126. 问：`raise` 的作用是什么？  
     答：主动抛出异常。

127. 问：自定义异常为什么有用？  
     答：能表达更明确的业务错误语义。

128. 问：什么情况下要重新抛出异常？  
     答：记录上下文后仍需要上层决策时。

129. 问：`assert` 适合做什么？  
     答：开发期断言，不适合替代正式输入校验。

130. 问：为什么线上逻辑不应依赖 `assert`？  
     答：优化模式下断言可能被移除。

131. 问：异常和返回错误码相比有什么优点？  
     答：错误路径更清晰，不会污染正常返回值。

132. 问：什么时候不该用异常做流程控制？  
     答：高频、可预期分支，不然会影响可读性和性能。

133. 问：如何获取异常对象？  
     答：`except Exception as e:`。

134. 问：如何打印完整异常栈？  
     答：可用 `traceback` 模块或日志的 `exc_info=True`。

135. 问：医疗项目中网络请求为什么要区分可重试和不可重试异常？  
     答：因为 HTTP 4xx 常是请求问题，而超时、断连可能重试可恢复。

## 六、模块、包与导入

136. 问：模块是什么？  
     答：一个 `.py` 文件就是一个模块。

137. 问：包是什么？  
     答：包含多个模块的目录，通常带 `__init__.py`。

138. 问：`__init__.py` 有什么作用？  
     答：标记包、执行初始化逻辑、控制导出接口。

139. 问：绝对导入和相对导入区别是什么？  
     答：绝对导入从包根路径找，相对导入从当前包层级找。

140. 问：为什么项目里常优先使用绝对导入？  
     答：更直观，运行方式变化时更稳定。

141. 问：`if __name__ == "__main__":` 有什么用？  
     答：区分脚本直接运行和作为模块被导入。

142. 问：为什么导入时不应执行重逻辑？  
     答：会增加副作用，影响测试、复用和启动速度。

143. 问：延迟导入有什么好处？  
     答：减少启动开销，避免不必要依赖。

144. 问：循环导入为什么危险？  
     答：会导致模块初始化未完成时相互引用，产生错误。

145. 问：如何减少循环依赖？  
     答：重构模块边界、抽公共层、局部导入。

146. 问：`__all__` 的作用是什么？  
     答：控制 `from module import *` 时导出的名称。

147. 问：`sys.path` 作用是什么？  
     答：控制 Python 的模块搜索路径。

148. 问：为什么运行方式会影响导入？  
     答：因为模块的包上下文和搜索路径会变化。

149. 问：`python -m package.module` 有什么优点？  
     答：按包方式运行，导入语义更稳定。

150. 问：项目中的双导入分支有什么价值？  
     答：兼容包运行和直接运行两种方式。

## 七、文件、编码与序列化

151. 问：为什么读文件常显式指定 `encoding="utf-8"`？  
     答：避免不同环境默认编码不一致。

152. 问：文本文件和二进制文件打开方式有何不同？  
     答：文本用 `t`，二进制用 `b`。

153. 问：`with open(...)` 的优势是什么？  
     答：自动关闭文件，异常时也更安全。

154. 问：`read()`、`readline()`、`readlines()` 区别是什么？  
     答：分别读取全部、一行、所有行列表。

155. 问：为什么大文件更适合逐行读取？  
     答：更省内存。

156. 问：JSON 适合什么数据？  
     答：结构化文本数据，跨语言友好。

157. 问：`json.dumps()` 和 `json.loads()` 区别是什么？  
     答：前者对象转字符串，后者字符串转对象。

158. 问：`ensure_ascii=False` 有什么作用？  
     答：保留中文，不转成 `\uXXXX`。

159. 问：为什么网络接口常用 JSON？  
     答：格式统一、易读、易跨系统传输。

160. 问：Pickle 有什么特点？  
     答：能序列化更多 Python 对象，但不安全且不跨语言。

161. 问：为什么不要反序列化不可信的 Pickle 数据？  
     答：可能执行恶意代码。

162. 问：CSV 适合什么场景？  
     答：表格型数据交换。

163. 问：路径处理为什么推荐 `pathlib`？  
     答：语义更清晰，跨平台更友好。

164. 问：项目里构造 `root_dir` 的意义是什么？  
     答：避免依赖当前工作目录，保证读取词典文件稳定。

165. 问：为什么不能把中文文本处理和编码问题混为一谈？

## 十、并发与异步

191. 问：进程和线程的区别是什么？  
     答：进程资源独立，线程共享进程内存。

192. 问：GIL 是什么？  
     答：CPython 中保证同一时刻只有一个线程执行字节码的全局解释器锁。

193. 问：GIL 是否表示 Python 不能并发？  
     答：不是，I/O 密集型仍可用线程并发，CPU 密集型更适合多进程。

194. 问：I/O 密集和 CPU 密集怎么区分？  
     答：前者主要等待外部资源，后者主要耗费计算。

195. 问：`threading` 适合什么场景？  
     答：I/O 密集任务，如网络请求、文件读写。

196. 问：`multiprocessing` 适合什么场景？  
     答：CPU 密集计算。

197. 问：`asyncio` 适合什么场景？  
     答：大量高并发 I/O 场景。

198. 问：协程和线程的核心区别是什么？  
     答：协程是用户态协作调度，线程由系统调度。

199. 问：`await` 的含义是什么？  
     答：等待一个可等待对象完成，并让出执行权。

200. 问：同步代码为什么更容易调试？  
     答：执行顺序直观，调用栈更简单。

201. 问：本项目当前 LLM 链路为什么使用同步实现？  
     答：结构简单、教学友好，便于逐步打印和理解主流程。

202. 问：如果要把 LLM 调用改成异步，主要收益是什么？  
     答：提升多请求场景下的吞吐量。

203. 问：并发场景下共享可变状态有什么风险？  
     答：竞态条件和数据不一致。

204. 问：锁的作用是什么？  
     答：保护临界区，避免并发冲突。

205. 问：死锁是什么？  
     答：多个执行单元互相等待对方释放资源，最终都无法继续。

## 十一、内存管理与性能

206. 问：Python 的内存管理主要依赖什么机制？  
     答：引用计数为主，辅以垃圾回收。

207. 问：什么是引用计数？  
     答：对象被引用的次数。

     答：因为循环引用不能仅靠引用计数回收。

210. 问：什么时候性能优化最值得做？  
     答：有明确瓶颈证据时。

211. 问：为什么不建议过早优化？  
     答：会增加复杂度，且可能优化错方向。

212. 问：Python 性能优化常见手段有哪些？  
     答：选对数据结构、减少拷贝、缓存结果、批量处理、必要时下沉到更快实现。

213. 问：为什么集合成员测试通常比列表快？  
     答：集合基于哈希，列表通常需要线性扫描。

214. 问：字符串拼接为什么常推荐 `''.join()`？

215. 问：什么是惰性加载？  
     答：用到时再初始化资源。

216. 问：项目里 `GraphClient` 懒加载的意义是什么？  
     答：调试实体识别或计划生成时不必提前要求数据库可用。

217. 问：日志过多有什么问题？

     答：便于按环境统一打开或关闭。

219. 问：大模型请求里为什么要截断日志内容？

220. 问：Aho-Corasick 相比逐词 `in` 匹配的优势是什么？

## 十六、结合本项目的 Python 题

276. 问：为什么 `EntityLinker` 在初始化时就加载词典？  
     答：因为词典是稳定数据，提前加载可减少每次查询的 I/O 成本。

277. 问：为什么 `EntityLinker` 要维护 `entities_by_type` 和 `word_types` 两份结构？  
     答：前者用于校验，后者用于从词反查类型。

278. 问：为什么 `link()` 里要删除被长词包含的短词？  
     答：避免短词误命中，优先保留更具体实体。

279. 问：为什么 `validate_entity()` 要通过 label 反查类型？  
     答：因为词典按实体类型组织，而计划校验输入是 Neo4j label。

280. 问：为什么 `IntentPlanner` 先判断 `linked_entities` 是否为空？  
     答：避免 LLM 在无约束状态下臆造实体和查询。

281. 问：为什么 `SUPPORTED_ACTIONS` 要单独定义？  
     答：便于统一做白名单校验。

282. 问：为什么 `_normalize_plan()` 只接受字典？  
     答：因为预期结构化输出是 JSON 对象，不接受任意文本。

283. 问：为什么 `query_property` 和 `query_relation` 要分两类处理？  
     答：它们的 schema 校验和 Cypher 结构不同。

284. 问：为什么 `CypherBuilder` 可以把 label 和 property 直接格式化进语句？  
     答：因为它们来自内部白名单，而不是用户自由输入。

285. 问：为什么 `subject_name` 仍然要走参数化？  
     答：它来源于用户问题映射结果，必须避免拼接注入。

286. 问：为什么关系查询要支持 `incoming` 和 `outgoing`？  
     答：同一关系既可能正查，也可能从终点反查起点。

287. 问：为什么 `GraphClient.run()` 收到空 Cypher 直接返回空列表？  
     答：保持接口稳定，并避免无意义数据库调用。

288. 问：为什么 `AnswerGenerator` 图谱无结果时不调用 LLM？  
     答：防止模型脱离事实自由发挥。

289. 问：为什么答案生成器要限制 `num_limit`？  
     答：避免上下文过长、回答拖沓和请求成本增加。

290. 问：为什么属性查询模板需要 `_stringify()`？  
     答：因为图谱属性可能是列表，不先转换无法自然输出。

291. 问：为什么 `_unique_non_empty()` 要保序？  
     答：结果展示更稳定，也更接近数据库原始顺序。

292. 问：为什么 `LLMClient` 要区分 `chat_json()` 和 `chat_text()`？  
     答：两类调用的输出约束和温度策略不同。

293. 问：为什么 `chat_json()` 温度设置为 0？  
     答：降低随机性，提升结构化输出稳定性。

294. 问：为什么 `chat_text()` 温度可以略高一点？  
     答：自然语言润色允许适度灵活，但仍要受图谱结果约束。

295. 问：为什么 `_post_chat()` 要做二次 `json.loads(content)`？  
     答：因为模型返回的 `content` 本身还是 JSON 字符串。

296. 问：为什么 `_send_with_retries()` 不重试 `HTTPError`？  
     答：因为多数 HTTP 业务错误不是重试能解决的。

297. 问：为什么要保留 `last_error` 字段？  
     答：让主流程能在最终输出前统一观察 LLM 失败原因。

298. 问：为什么 `LLMChatBotGraph` 不在构造时立刻连 Neo4j？  
     答：为了让前半段逻辑能独立调试，减少环境依赖。

299. 问：为什么主流程每一步都做空结果短路返回？  
     答：降低嵌套复杂度，并明确每层失败边界。

300. 问：如果面试官问“这个项目体现了哪些 Python 工程能力”，你怎么答？  
     答：可以从模块拆分、依赖最小化、白名单校验、参数化查询、异常分类重试、懒加载、模板兜底、调试样例和可替换 LLM 接口这几个点展开。
